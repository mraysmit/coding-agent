APEX AI Agent — Help

Architecture, agentic workflow, tools, and configuration reference

Overview

The APEX AI Agent generates, validates, and executes APEX YAML business rule configurations from natural language requirements. It is built with Spring Boot 4.0.2 and Spring AI 2.0.0-M2, using OpenAI GPT-4o as the backing LLM.

The application supports two interfaces: a Web UI (this application) and an optional CLI REPL for interactive terminal use.

Agentic Architecture

This application uses agentic AI flow — the LLM autonomously decides which tools to call, observes results, and iterates until the task is complete. This happens at two layers:

1. Autonomous Agent ReAct Loop

The ChatClient is configured with a ToolCallAdvisor that enables autonomous multi-step tool calling. The LLM receives a user prompt, decides which tools to invoke (file I/O, grep, shell commands, APEX-specific tools), observes the results, and continues calling tools until it produces a final answer. This is a classic ReAct-style agent loop.

2. Orchestrated Agent Pipeline Generation Service

The ApexGenerationService runs a structured multi-step pipeline where code controls the high-level workflow, but each step uses the LLM agentically with full tool access:

User Prompt
→
LLM + Tools
→
Generate YAML
→
Compile
→
Execute
→
Validate
→
Output

If validation fails, the agent retries with error feedback (up to 3 attempts)

Key Agentic Components

ComponentRole
ToolCallAdvisor Enables autonomous multi-step tool calling — the LLM decides what to call and when
maxAttempts retry loop Outer safety net that re-prompts the agent if it doesn't produce valid YAML
buildRetryPrompt() Feeds previous failures back to the agent so it can self-correct
MessageWindowChatMemory 50-message sliding window for conversational context across REPL interactions

How to Use the Web UI

  1. Business Requirements — Describe the rules you want in plain English. Be specific about conditions, thresholds, and outcomes.
  2. JSON Data Structure — Provide a sample JSON object that the rules will evaluate. This tells the agent what fields are available.
  3. Hints (optional) — Comma-separated keywords to guide the generation (e.g., eligibility, classification, score-based).
  4. Click Generate Rules — The agent will generate YAML, compile it, execute it against your data, and validate the output.
  5. Review the Validation Results — Each stage (Lexical, Compilation, Execution, Expectations) shows pass/fail. Click a chip to see details.
  6. Download or copy the Generated Files from the results panel.

Configuration Reference

Key properties in application.yaml:

PropertyDefaultDescription
app.repl.enabled false Enable the interactive CLI REPL. When true, the app starts a terminal-based chat loop instead of running as a web-only server.
apex.knowledge.enabled false Enable the RAG vector store for semantic search over APEX documentation. Requires an embedding model API.
apex.knowledge.project-root ../apex-rules-engine Path to the APEX rules engine project for knowledge ingestion.
spring.ai.openai-sdk.chat.options.model gpt-4o The LLM model to use for generation and chat.
server.port 8080 Web server port (standard Spring Boot property).

Running the Application

Web UI (default)

# Set your API key
export OPENAI_API_KEY=your-key-here   # Linux/macOS
$env:OPENAI_API_KEY="your-key-here"   # Windows PowerShell

# Start the server
./mvnw spring-boot:run

# Open http://localhost:8080/home

CLI REPL (optional)

# Enable the REPL via command line
./mvnw spring-boot:run -Dspring-boot.run.arguments="--app.repl.enabled=true"

# Or via standalone jar
java -jar target/apex-ai-agent-0.0.1-SNAPSHOT.jar --app.repl.enabled=true

Build a Standalone Jar

./mvnw clean package -DskipTests
java -jar target/apex-ai-agent-0.0.1-SNAPSHOT.jar
